Temporary tests used to prove H1–H3 were modeled on `tests/agent.test.ts` scaffolding (mocked `chrome`, mocked `callJevProvider`, `AgentRunner` with `stepDelayMs: 0`); they were removed after the run, so the claims below are the durable record.

- H1 proof: 3 × `SCROLL_DOWN` decisions → `blocked`, error `The same action "SCROLL_DOWN Scroll down" was repeated 3 times without reaching the goal.`
- H2 proof: Stop during trusted `CONTENT_PREPARE` → `CONTENT_DISPATCH` synthetic fallback sent after Stop; `status: idle`, `steps recorded: 1`, `logs: 1`.
- H3 proof: model alternates DONE (with `goal_done: 0.1`) and CLICK → logs `CLICK, DONE (vetoed), CLICK, DONE (vetoed), CLICK, DONE (vetoed)`, i.e. three vetoes in one run.

## End-to-end flow, with the failure point at each stage

1. **Start** — popup `START_AGENT` → `resolveTabId` → `refreshRunnerSettings` → `runner.start` (fire-and-forget) → `reset()` → `attachInput` (chrome.debugger) → loop.
   *Failures:* popup ignores the error response, so "no active tab"/storage errors are silent (`src/popup/Popup.tsx:67-79`). Stop during `attachInput` can leave the debugger attached (attach resolves after `stop()` detached).
2. **Observe** — `followTab` → `ensureContentScriptReady` (internal-scheme refusal, PING, inject `content.js`, up to 6 attempts) → `CONTENT_OBSERVE` → viewport-only snapshot: interactive controls with role/label/value/href/section, visible text ≤6000 chars, `SCROLL_UP/DOWN`, `PRESS_ENTER`, `WAIT`.
   *Failures:* any observe error is **fatal** (`src/background/agent.ts:354-357`); no retry for navigation-race messages. `ensureContentScriptReady` has **no runToken check** — Stop can take ~6+ s to take effect (`agent.ts:315-325`).
3. **Resolve previous action / guards** — fingerprint, `describeOutcome`, 3× no-change deadlock, repeat count, target suppression, visited URLs.
   *Failures:* suppression is by **positional snapshot id**; cross-tab follow doesn't clear counters; repeat rule counts scroll/pagination (H1).
4. **Decide** — `buildJevRequest` (elements + `operation`, per-operation target questions, `goal_done`, `stuck`) → provider → strict `validateChoiceAnswer` (invalid → one retry, then error).
   *Failures:* DONE/BLOCKED veto repeats per proposal, not once (H3). Provider request has no timeout (M2).
5. **Terminal handling** — DONE vetoed if `goal_done < 0.5`; BLOCKED vetoed if `stuck < 0.5` **and history < 6**; hesitant terminal (<0.5 confidence) gets one 600 ms second look.
6. **TYPE_TEXT** — text helper generates the value; refusal ("no value") is fed back to the model.
7. **Act** — page-side `prepareAction`: freshness → wait/scroll/select/direct-value → scroll into view → stable point → covered check → clear+focus; then trusted CDP input or synthetic events; `settle()`.
   *Failures:* no token check after `act()`; debugger-failure fallback dispatches synthetically **after Stop** (H2); direct `date`/`number` assignment is never verified (M9).
8. **Record & continue** — history/step/log; wait for load if navigating; follow new tab; loop with `stepDelayMs`.
9. **Exit** — DONE/BLOCKED, step budget, 3 no-change, 3 repeats/6, 2×maxSteps model calls, invalid answer twice, or any error. All exits broadcast + detach.

## Findings — High

### H1. Repeat blocker kills legitimate scrolling/pagination — verified
`REPEAT_LIMIT=3` within `REPEAT_WINDOW=6` (`src/background/agent.ts:80-83,400-405`) counts every non-wait action by exact string `"<OP> <label>"` (`repeatCount`, `agent.ts:656-659`). `SCROLL_DOWN` is counted, and cross-snapshot suppression never matches scroll (`OP_BY_KIND` maps scroll→`''`, `agent.ts:68`; label-match only at `agent.ts:413-416`). Because observation is viewport-only, long pages need repeated scrolls — the two mechanisms directly conflict. Same for pagination clicks whose label is stable ("Next page").

- Evidence: 3 × `SCROLL_DOWN` → `blocked`, `The same action "SCROLL_DOWN Scroll down" was repeated 3 times without reaching the goal.`
- Fix direction: exempt `scroll` (and likely `key`) from the repeat block, or key repeats by node/label; make suppression match controls too.

### H2. Stop is not authoritative — verified
No `runToken` check after `act()` (`agent.ts:566-628`). Stop during a trusted action → `act()` catch falls back to `CONTENT_DISPATCH` (`agent.ts:705-710`) → **synthetic action executed after Stop**, and history/log/step are still recorded.

- Evidence: Stop during `CONTENT_PREPARE` → fallback sent, `status: idle`, `steps: 1`, `logs: 1`.
- Also: the provider `fetch` is not aborted; `ensureContentScriptReady` ignores Stop for up to ~6 s; an already-sent trusted command cannot be recalled.
- Fix direction: check `runToken` after `act()`; skip fallback and history writes if the token changed; add token checks inside `ensureContentScriptReady`; abort in-flight fetch on Stop.

### H3. DONE veto repeats every proposal; docs say "withheld once"
`vetoed` is cleared after one withholding (`agent.ts:435-440`), so each new DONE with `goal_done < 0.5` is vetoed again. README line 45 promises one withholding.

- Evidence: logs `CLICK, DONE (vetoed), CLICK, DONE (vetoed), CLICK, DONE (vetoed)` — 3 vetoes in one run.
- BLOCKED has the same repeat behavior and additionally is only vetoed while `history.length < 6` (`agent.ts:472`): after 6 actions a `stuck=0.0` BLOCKED is accepted, contradicting README line 45.
- Note: if a provider re-answers a withheld `DONE` anyway, strict validation rejects it → one retry → run ends `error`, not `blocked`.

### H4. Run can wedge at "running" forever
`start()`/`step()` are fire-and-forget (`agent.ts:206-212`) and `executeOneStep` has only partial try/catch (observe, provider, act). Anything thrown in `summarize`/`buildJevRequest`/`addLog` (e.g. a malformed snapshot after an extension update) rejects into `void runner.start(...)` → status stays `running`, popup shows a live run that never ends. Compounding: MV3 service-worker restart loses all run state (in-memory only, `docs/PRIVACY.md:18`); popup does not poll, so it can display a stale "running" run indefinitely.

- Fix direction: wrap `executeOneStep` in try/catch → `finish('error', …)`; consider `chrome.storage.session` persistence for run state.

### H5. Suppression targets the wrong thing after DOM changes
`targetFailureCount`/`suppressedTargetIds` are snapshot-local ids `e1…en` (`agent.ts:375-380,406-408,556,583`; `src/shared/action-space.ts:100-111`). Ids are positional, so after any re-render a suppressed id can name a different element.

- Additionally, `state.elements` still lists suppressed elements with their operations (`action-space.ts:52-98` runs before suppression at `100-111`), while target question criteria omit them — the model can pick an index it can see but that is not a valid target → `Invalid target choice` → one retry → run error.
- Cross-tab follow also skips clearing counters: `agent.ts:366-371` takes the `tabNote` branch and never reaches the `page_changed` clear at `378-380`.
- Fix direction: suppress by label+operation (like repeats) or stable element identity; remove suppressed targets from `state.elements` or keep both views consistent; clear `targetFailureCount` on tab follow.

### H6. Freshness guard is over-strict for live pages
For click/select, `isFresh` compares `pageKey` — which includes **every** safe input's `value/checked/selectedIndex/disabled/readOnly` plus scroll/viewport (`src/content/snapshot.ts:216-238`) — and a scope `innerText` up to 6000 chars (`guard`, `snapshot.ts:240-260`). An unrelated auto-updating input, a clock/chat/carousel in the same `li/form/article`, or a scroll invalidates the decision → `stale`; after `MAX_CONSECUTIVE_STALE=4` the run ends with `Page kept changing before actions could run`. On dynamic pages this can make the agent unable to act at all. For fill/key, `isFresh` re-runs the whole `readState()` (full DOM + text walk) per action — also a perf cost.

- Fix direction: narrow the click/select guard to the target plus its immediate form/row context; drop unrelated input values from `pageKey`; consider allowing a retry for the specific element when only unrelated parts changed.

## Findings — Medium

### M1. Observe errors are fatal, including navigation races
`isNavigationError` is only used around `act` (`agent.ts:591-599`); `"Receiving end does not exist"` / `"Frame was removed"` on `CONTENT_OBSERVE` ends the run (`agent.ts:354-357`). A click whose navigation outruns `waitForTabToLoad` (8 s cap, `agent.ts:266-289`) can kill the run it just triggered.

### M2. No fetch timeout/abort; retry set is narrow
`postJson` retries but has no `AbortController` (`src/shared/providers/http.ts:9-54`); a hung provider leaves the run "running" indefinitely, and Stop cannot cancel it. Only 429/503/529 are retried (`http.ts:1`); 500/502/504/408 are not.

### M3. Helper-refusal counter shares the stale counter
`consecutiveStale` is incremented on "nothing typed" (`agent.ts:551-559`); four consecutive refusals on **different** fields end the run with the misleading `Text helper failed: …`, even though each refusal was handled correctly (README: withheld after two attempts, run continues).

### M4. Tab-follow edge cases
- `onTabRemoved` with an empty stack leaves `activeTabId` pointing at a dead tab → next observe errors (`agent.ts:133-138`).
- If the opener tab is closed while the agent is on the followed tab, the dead id stays on the stack.
- Multiple tabs opened by one click: only the first is followed.
- Tabs opened with `rel=noopener` may not carry `openerTabId` and thus may not be followed (untested — needs a real Chrome check).
- Ad/popup tabs opened by the page can hijack the run.

### M5. `npm run package` is broken on Windows
`new URL('..', import.meta.url).pathname` yields `/C:/…`; `path.join` produces `\C:\…` → `existsSync` false → false `dist/manifest.json missing` (`scripts/package.mjs:15`). Verified on this machine; CI (Ubuntu) is unaffected. Use `fileURLToPath` as `vite.config.ts` does.

### M6. `npm ci` fails on npm ≥11.6/12 defaults
Dependency is a git URL (`package.json:38`; lockfile `git+ssh://…#1a926dd…`); npm 12 defaults `allow-git=none` → `EALLOWGIT`. Workaround used: `npm ci --allow-git=all --ignore-scripts` then build `jev-dev-kit` with `tsc`. CI (Node 22 / npm 10) passes; contributors on newer npm won't. Publishing dev-kit to npm or pinning the HTTPS codeload tarball fixes this.

### M7. `content.js` build fragility
It must stay import-free (content scripts are not modules). Today it is, but any future value import shared with `background` would make Rollup emit a shared chunk and silently break the content script; there is no build-output guard (`vite.config.ts:13-32`).

### M8. Unbounded request payload
`accessibleName` has no length cap (`snapshot.ts:112-162`), and a `<select>` with hundreds of options becomes hundreds of element options + target criteria (`snapshot.ts:322-337`, `action-space.ts:128-141`). 250 elements × long labels/options can produce very large decision requests (cost/latency/timeout risk). `omitted_actions` is computed but never sent (`snapshot.ts:408`).

### M9. Direct-value writes are unverified
`date/datetime-local/month/week/time/color/range/number` are assigned directly and reported as success (`src/content/executor.ts:137-143`); an invalid value (e.g. natural-language date) silently becomes `''`. The next observation usually recovers, but the step is recorded as executed and can feed the deadlock counter.

### M10. Mid-run settings changes are inconsistent
`SAVE_SETTINGS` replaces live settings (`agent.ts:166-171`): changing provider/keys mid-run applies immediately, but toggling `trustedInput` off does **not** stop CDP use (`act` only checks `input.attachedTab`, `agent.ts:686`), and turning it on won't attach until the next tab switch.

### M11. Cloudflare error envelope
`{success:false, errors:[…]}` with HTTP 200 falls through to a generic `Missing answer object` (`src/shared/providers/cloudflare.ts:26-34`).

## Findings — Low / docs / polish

- `README.md:35-36`: `## How it works` appears twice.
- CHANGELOG 1.5.0 references `npm run build:test`, which no longer exists in `package.json`.
- `src/content/index.ts:15` comment says `document_idle`; manifest says `document_end` (`public/manifest.json:45`).
- `describeOutcome` reports `page changed: "title"` but `page_changed` is fingerprint-based and excludes the title → contradictory context for title-only changes (`agent.ts:41-48,374`).
- `parseFieldText` accepts extra keys despite the test name claiming otherwise (`jev-dev-kit` `src/text.ts:30-32`); the fence-stripping regex also mangles a value containing backticks.
- Helper key sharing keys off `baseUrl.includes('openrouter.ai')` (`src/shared/text-helper.ts:62`) — a lookalike host would receive the OpenRouter key (self-inflicted typo risk).
- Popup silently ignores `sendMessage` error responses; Run from a paused run silently restarts from scratch (`Popup.tsx:67-79`).
- Options numeric fields accept negatives (`src/options/Options.tsx:398-419`); negative `maxSteps` immediately blocks a run.
- `INTERNAL_PREFIXES` misses `chrome-untrusted://` (`agent.ts:75`); `waitForTabToLoad` timeout then observe can act on a half-swapped document.
- E2E harness finds the tab with `startsWith(url)` (`scripts/e2e-extension.ts:154-157`) — breaks on redirects; log slicing can miss entries past the 50-log cap (`178-187`).
- Overlay badge numbering can diverge from model element indices (`PRESS_ENTER` carries a node; `src/content/overlay.ts:31-63` vs `action-space.ts:61-98`).

## Test-coverage gaps

No tests for: repeat-block on scroll/pagination; Stop mid-act/injection; repeated veto; suppression id drift; elements-vs-targets mismatch; cross-tab counter carryover; observe navigation-race retry; fetch timeout; tab-close stack edges; direct-value validation; `package.mjs` on Windows; build-output import-freeness of `content.js`; negative settings.

## What the code does well (verified)

- Strict answer validation with rounding tolerance (`jev-dev-kit` `src/validate.ts`: tolerance 0.015, sum tolerance 0.02).
- Freshness + covered checks before input; single-click semantics; no implicit Enter.
- Internal-page refusal; password/file/hidden exclusion from observation.
- Settings migration for obsolete model ids; retry with backoff; clear error messages.
- Deterministic build/zip checks (on Linux); 88 focused tests that never hit a paid API.

## Suggested fix order (smallest correct change first)

1. Exempt `scroll` (and probably `key`) from the repeat block, or key repeats by node/label; make suppression match controls too (`agent.ts:400-416,656-659`).
2. Check `runToken` after `act()`; skip the synthetic fallback and history/log writes if the token changed; add token checks inside `ensureContentScriptReady`; abort in-flight fetch on Stop (`agent.ts:566-628,705-710,315-325`).
3. Make suppression consistent: suppress by label+operation or stable identity, and keep `state.elements` in sync with target criteria; clear `targetFailureCount` on tab follow (`agent.ts:366-380`; `action-space.ts:100-111`).
4. Wrap `executeOneStep` in try/catch → `finish('error', …)`; retry observe once on `isNavigationError` (`agent.ts:337-357`).
5. Timeout provider requests (`AbortController`), retry 500/502/504; handle Cloudflare `success:false` (`http.ts`, `cloudflare.ts`).
6. `package.mjs`: use `fileURLToPath`; document `--allow-git=all` or move dev-kit to npm/tarball (`scripts/package.mjs:15`; `package.json:38`).
7. Docs fixes (duplicate heading, `build:test`, `document_idle`, "withheld once").
